# ERP 本地部署指南

> 适用对象：在本地（开发机 / 内网服务器）从零把 ERP 跑起来的人。
> 基于 `erp_source` 工程实测整理，结论先行，步骤可直接照抄。

---

## 〇、先说结论（4 个关键约束，先看）

| # | 约束 | 后果 | 正确做法 |
|---|------|------|----------|
| 1 | **`migrations/*.sql` 不能从零建库**（0001 引用未建出的 `user_profile` 类型，需既有库做底座） | 顺序跑 migrations 必失败，库建不出来 | 用 `pg_dump` 复刻已有 `erp_db` 的结构+数据来初始化 |
| 2 | **前端生产构建（vite build）当前不可用**（缺 `@rolldown/binding-darwin-universal` 原生绑定） | `npm run build:client` 失败 | 本地用 `vite dev` 模式（端口 5173），不要碰生产打包 |
| 3 | **`.env` 被排除在 git/zip 外** | 克隆/解压后没有连接串，服务起不来 | 需自行准备 `.env`（见第四节） |
| 4 | 后端 `nest build` 依赖 `@swc/core` 平台原生绑定（npm optional-dep 偶发漏装） | 报 `Failed to load native binding` | 已在 `package.json.optionalDependencies` 固化；若仍缺，补对应平台包 |

后端（`nest build` / `nest start`）已恢复可用；数据库 schema 类型与 **PostgreSQL 16** 绑定，请勿用其他大版本。

## 三、准备数据库（最易踩坑）

### 场景 A：本机已带 `.pgdata`（当前工程即此状态）
数据目录 `erp_source/.pgdata` 随工程提交，**`postgresql@16` 已实例运行在端口 5434**，库 `erp_db`、用户 `erp` 已就位。
→ **直接跳过本步，去第五节装依赖即可**。

验证：
```bash
PGPASSWORD=erp psql -h localhost -p 5434 -U erp -d erp_db -c "SELECT count(*) FROM information_schema.tables WHERE table_schema='public';"
```

### 场景 B：全新机器（从零部署）
1. 安装 PG16：
   ```bash
   brew install postgresql@16
   brew services start postgresql@16   # 或 pg_ctl 手动起
   ```
2. **从源机器导出已有库**（这是唯一可靠的初始化方式）：
   ```bash
   # 结构 + 数据
   pg_dump -h localhost -p 5434 -U erp --no-owner --no-acl erp_db > erp_db.sql
   # 若只要结构：追加 --schema-only
   ```
   > ⚠️ 不要用 `migrations/*.sql` 初始化——它依赖既有库做底座，无法从零跑通。
3. 新机器建用户 / 库 / 导入：
   ```bash
   createuser -s erp                 # 超级用户（或用 psql 建带密用户）
   createdb -O erp erp_db
   psql -U erp -d erp_db -f erp_db.sql
   ```
4. 确认监听端口为 **5434**（或改 `.env` 连接串为实际端口）。

## 四、准备 `.env`

工程根需有 `.env`（被 git/zip 排除，必须自己准备）。**必需变量**：

```dotenv
# 数据库连接（最关键）
SUDA_DATABASE_URL=postgres://erp:<密码>@localhost:5434/erp_db

# 日志目录
LOG_DIR=./logs
```

可选 / 功能相关（本地可先留空，参考已有 `.env`）+：

| 变量 | 用途 |
|------|------|
| `FORCE_AUTHN_INNERAPI_DOMAIN` | 内部 API 鉴权域名 |
| `ERP_UPSTREAM_TOKEN` | ERP 上游调用令牌 |
| `ERP_RECEIVER_ALLOWED_IPS` | 接收方允许 IP 白名单 |
| `LOG_REQUEST_BODY` / `LOG_RESPONSE_BODY` | 是否记录请求/响应体 |

> 注：`scripts/dev-local.js` 还会读 `.env.local`（沙箱 `env pull` 产物）。**纯本地部署只需 `.env` 即可**，`.env.local` 可省略。

## 五、安装依赖

```bash
cd erp_source
npm install
```

- `postinstall` 会执行 `fullstack-cli action-plugin init`（需联网，失败仅告警，不阻断）。
- 若之后 `nest build` 报 `Failed to load native binding`：确认 `package.json` 的 `optionalDependencies["@swc/core-darwin-arm64"]` 已存在；其他 OS/arch 需类比补装对应 `@swc/core-<platform>` 包。

## 六、启动（本地开发，推荐）

**方式一：一键（会尝试拉取沙箱凭证，失败仅 warn）**
```bash
npm run dev          # → dev.sh → dev-local.js，并发起 server + client
```

**方式二：稳妥分体（推荐，避免 env pull 网络依赖）**
```bash
# 终端 1：后端（nest start --watch，热重载，端口 3000）
npm run dev:server

# 终端 2：前端（vite dev，端口 5173）
npm run dev:client
```

- 后端端口优先级：`SERVER_PORT` → `PORT` → 默认 **3000**。
- 前端 dev 端口：**5173**，模板预设已处理 `/api` 代理到后端，无需手配。

## 七、生产构建（受限）

```bash
npm run build        # build.sh：server+client 并行构建 + 智能依赖裁剪
npm run start        # 从 dist/ 启动（= scripts/run.sh: NODE_ENV=production node server/main.js）
```

⚠️ **当前限制**：
- ✅ `build:server`（`nest build`）已验证可用（247 文件 swc 编译，0 错）。
- ❌ `build:client`（`vite build`）因缺 `@rolldown/binding-darwin-universal` **失败**。
  → 如需生产前端，须先装回 rolldown 原生绑定或切换构建器；在此之前请坚持用 `dev:client`。

## 九、已知坑清单（务必先看）

1. **migrations 不能从零建库** → 用 `pg_dump` 复刻（见三-B）。
2. **vite 生产构建不可用** → 本地用 `vite dev`（见七）。
3. **`.env` 被排除** → 自行准备（见四）。
4. **swc 原生绑定 optional-dep bug** → 安装后若 build 失败，补对应平台包（见五）。
5. **前后端端口分离**（3000 / 5173）→ dev 模式靠模板代理联通，勿手动改端口导致跨域。
6. **`nest build` 清 dist 需谨慎**：`nest-cli.json` 设 `deleteOutDir:false`，`build.sh` 第 5 步会把 `.env`、`run.sh` 拷进 `dist/`；若手动删 `dist` 请用工具确认，避免误删大目录卡住。
