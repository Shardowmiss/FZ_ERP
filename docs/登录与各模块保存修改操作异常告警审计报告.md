## 三、核心发现 1：数据库约束翻译在真实链路中失效（已修复）

### 现象
上一轮治理把 `23503/23505/23502/23514` 翻译成具体中文，但只用手工构造的错误对象做了单测。**真实链路里 drizzle 会把底层 `PostgresError` 包成 `DrizzleQueryError`**，真实 `code`/`detail`/`constraint_name` 只在 `.cause` 上：

```
CAPTURED name= Error  code= undefined  ctor= DrizzleQueryError
cause.code= 23503  cause.ctor= PostgresError
cause.detail= Key (id)=(xxx) is still referenced from table "purchase_order".
```

旧 `translateDbConstraintError` 只读顶层 `.code`（undefined）→ 返回 null → 过滤器兜底 500「服务器内部错误」。**即：生产环境里所有「该数据已被引用，不允许删除」仍显示为系统故障。**

### 修复（已应用并验证）
- `server/common/errors/db-constraint.ts`：`translateDbConstraintError` 增加 `.cause` 解包 + 兼容 `constraint_name` 字段（`dbErrorFields` 助手）。
- `server/common/filters/exception.filter.ts`：非 `HttpException` 分支改为「**先翻译约束冲突 → 再判 22P02 → 兜底 500**」。

### 动态验证（真实业务数据，`error-alert-audit.spec.ts` B1）
1. 真实插入 `供应商 SUP-AUDIT` → 插入 `采购订单 PO-AUDIT-001`（引用该供应商）
2. 执行 `delete from supplier` → 捕获到 `DrizzleQueryError`
3. 喂给过滤器 → **修复前返回 500「服务器内部错误」；修复后返回 409「该数据已被「采购订单」引用，不允许删除或修改」**

> 影响面：全库所有主数据「被引用/重复/必填」场景（供应商、款号、仓库、门店、SKU、客户……）均随之生效，一处修复全局受益。

### 4.3 建议修复文案（统一映射 + 示例）

**原则**：裸 `Error` 一律改为 Nest `HttpException` ——「不存在」类用 `NotFoundException`(404)、「必填/格式/规则」类用 `BadRequestException`(400)、需携带业务码/详情的用 `BusinessException`。这样过滤器才能透出原中文文案，业务人员看得懂、运维能按文案定位。

**示例 1（业务不存在 → NotFoundException）**
```ts
// 之前
if (!m) throw new Error('会员不存在');
// 之后  ⬇ 404，过滤器透出「会员不存在」
if (!m) throw new NotFoundException('会员不存在');
```

**示例 2（入参必填 → BadRequestException）**
```ts
// 之前
if (!body?.orderId) throw new Error('orderId 必填');
// 之后  ⬇ 400，过滤器透出「orderId 必填」
if (!body?.orderId) throw new BadRequestException('orderId 必填');
```

**示例 3（业务规则拦截，需 force → BadRequestException / BusinessException）**
```ts
// 之前
throw new Error('当前已存在已分配/在库的唯一码…请传 force=true');
// 之后（带业务码，便于前端区分是否需要二次确认）
throw new BusinessException(
  ResponseCode.BUSINESS_ERROR,
  '当前已存在已分配/在库的唯一码，关闭唯一码开关会导致既有码失去校验依据；如需关闭请显式传 force=true',
);
```

**注意点**
- `BadRequestException` / `NotFoundException` / `ForbiddenException` / `UnauthorizedException` 均从 `@nestjs/common` 导入（多数文件已导入）。
- 若需返回非 4xx/带 `details`/`fieldErrors`，用 `BusinessException`（`@server/common/interfaces/exception.interface`，配合 `ResponseCode`）。
- 模板字符串类（含 `${skuId}` 等变量）保持变量即可，改为 `NotFoundException(\`...\`)` 后文案更具体。
- 不用改前端：上一轮已让前端 `errMsg()` 透出后端具体消息，后端文案一改，前端告警即同步变具体。
